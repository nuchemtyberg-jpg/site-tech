# SiteTech — Phase 5: Bidding / Opportunity Pipeline Dashboard

We have already implemented the core Opportunity / RFP architecture in SiteTech.

Existing related systems include:

- Customers / Companies
- Multiple Contacts
- Projects
- Opportunities
- Opportunity statuses
- Opportunity status history
- Opportunity Contacts
- Todos / My Work
- Workflow automation
- Notifications
- Email infrastructure
- Communications
- Activity / audit logging
- User permissions

The next phase is to build the primary user-facing Bidding / Opportunity management experience.

This phase should create the interface that SiteTech employees use every day to manage incoming RFPs and bids from initial receipt through Awarded, Lost, or No Bid.

Do NOT build estimating, takeoff, proposal generation, or pricing functionality yet.

The goal of this phase is visibility, organization, workflow, and efficient management of Opportunities.

--------------------------------------------------
1. PRIMARY NAVIGATION
--------------------------------------------------

Add a main navigation item called:

Bidding

or:

Opportunities

Preferred user-facing name:

Bidding

The technical entity can remain Opportunity.

The Bidding section should open to the main Bidding Dashboard.

Do not put pre-award work into the Projects navigation.

Maintain the architectural distinction:

Opportunity = potential/pre-award work

Project = awarded work

- What bids are due soon
- Which opportunities need attention

- Where each opportunity is in the pipeline

7. DRAG AND DROP STATUS CHANGES
--------------------------------------------------

IMPORTANT:

Dragging a card into another status must use the existing centralized Opportunity Status Change backend/service.

Do NOT directly update the database status from the frontend.

The status change must continue to:

- validate permissions
- record status history
- record activity
- trigger workflow rules
- generate Todos
- generate notifications

Examples:

Lost
→ require Lost Reason

No Bid
→ require No Bid Reason

Awarded

Open an appropriate modal before completing the transition.

--------------------------------------------------
FINAL IMPLEMENTATION INSTRUCTION
--------------------------------------------------

Before coding, inspect the Opportunity architecture implemented in Phase 4 and reuse it.

Do not create a second Opportunity model or duplicate status logic.

The most important operational goals of this screen are:

1. Know what SiteTech is currently bidding.
2. Know when each bid is due.
3. Know who is responsible.
4. Know what stage each opportunity is in.
5. Know what needs attention.

Keep those goals ahead of decorative dashboard features.

Build the Bidding interface as a practical construction preconstruction tool that can later expand into Scope, Takeoff, Estimating and Proposal functionality without requiring a redesign.
